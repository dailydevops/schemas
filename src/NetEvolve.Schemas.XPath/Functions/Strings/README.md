# String functions

The XPath 2.0 string functions of the Functions and Operators, section 7, on top of the function registry
(`Functions/Binding`). One registration file (`Registration.cs`) stages the group into the default catalog; one sealed
class per function.

| Function                                                                          | Arity | Notes                                                                         |
| --------------------------------------------------------------------------------- | ----- | ----------------------------------------------------------------------------- |
| `fn:concat`                                                                       | 2..n  | variadic; an empty sequence is the zero-length string                         |
| `fn:string-join`                                                                  | 2     | the one-argument form is XPath 3.0 (XP-71, #334)                              |
| `fn:substring`                                                                    | 2..3  | rounds as `fn:round` rounds; NaN and infinite arguments follow the text       |
| `fn:string-length`, `fn:normalize-space`                                          | 0..1  | without an argument they read the context item                                |
| `fn:translate`                                                                    | 3     | the first occurrence in the map string wins                                   |
| `fn:contains`, `fn:starts-with`, `fn:ends-with`, `fn:substring-before`, `fn:substring-after` | 2..3  | the third argument is the collation                         |
| `fn:upper-case`, `fn:lower-case`                                                  | 1     | full case mappings (a sharp s gives two letters); Final_Sigma  |
| `fn:normalize-unicode`                                                            | 1..2  | NFC, NFD, NFKC, NFKD                                                          |
| `fn:codepoints-to-string`, `fn:string-to-codepoints`                              | 1     | FOCH0001 for a value that is not a character of XML                           |

All functions count and index in Unicode code points. They are span based: a result is built in a stack buffer that grows
into a pooled array (`TextBuilder`), so only the result string is allocated, and a function that changes nothing returns
its argument. `fn:string-length`, `fn:contains`, `fn:starts-with`, and `fn:ends-with` allocate nothing.

## Embedded Unicode tables

Case mapping and normalization follow the one pinned **Unicode 18.0.0** (the version of `tests/conformance/suites/ucd.json` and of
`UnicodeTables.Version` in the Xml package) on every target framework (`netstandard2.0`, `net10.0`, `net11.0`).
Neither the case mapping of the runtime (`ToUpperInvariant`, `ToLowerInvariant`) nor `string.Normalize` is used: they follow the
Unicode version and the platform of the running process, and the first cannot apply the full mappings the specification asks for.

- `CaseMappingTables.generated.cs`: the simple mappings of `UnicodeData.txt`, overridden by the unconditional rows of
  `SpecialCasing.txt`, and the `Cased` and `Case_Ignorable` ranges of `DerivedCoreProperties.txt` for the Final_Sigma rule.
- `NormalizationTables.generated.cs`: the canonical combining classes, the full canonical and compatibility decompositions
  (Hangul is computed by the algorithm), and the primary composites without the composition exclusions
  (`Full_Composition_Exclusion` of `DerivedNormalizationProps.txt`).

Both files are generated by `StringTablesGenerator` in `tests/NetEvolve.Schemas.XPath.Tests.Unit/Functions/Strings`, and the test
`StringTablesTests` fails when a committed file differs from the generator output. To move to a new Unicode version:

1. Update `url` and `sha256` in `tests/conformance/suites/ucd.json`, and `UnicodeTables.Version` in the Xml package (see the
   README of `Text/Unicode` there).
2. Run the tests of this folder with the variable set, which rewrites the files instead of only comparing them:

   ```shell
   SCHEMAS_UCD_REGENERATE=1 dotnet test --project tests/NetEvolve.Schemas.XPath.Tests.Unit -f net10.0 \
     --treenode-filter "/*/*/StringTablesTests/*"
   ```

3. Run the whole test project. `CaseMappingTests` compares every code point with the pinned files, and
   `UnicodeNormalizationTests` runs `NormalizationTest.txt` of the pinned release for the four forms.

## Limitations

- Case mapping is culture-invariant: the Lithuanian, Turkish, and Azeri rows of `SpecialCasing.txt` are not applied. The
  Final_Sigma rule is applied by `fn:lower-case` (a capital sigma at the end of a word becomes the final small sigma U+03C2).
- Only the codepoint collation is supported (`CollationArgument`); any other collation is FOCH0002 (#123 AP19, DEF-43 #55,
  DEF-76 #88). An ordinal comparison of the code units is the codepoint collation for valid strings.
- The fully-normalized form of `fn:normalize-unicode` is not supported and raises FOCH0003 (DEF-75, #87).
- A surrogate that is not part of a valid pair counts as one code point of its own and maps to itself.
- `fn:encode-for-uri`, `fn:iri-to-uri`, and `fn:escape-html-uri` live in `Functions/QNames` (XP-28, #270; #96); the functions that use
  regular expressions live in `Functions/Regex`. `fn:compare` and `fn:codepoint-equal` belong to XP-25 (#267).
